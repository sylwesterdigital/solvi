# Solvi XR — vanilla JavaScript / Three.js

A WebXR prototype for the Rantlist.me Solvi assistant (pilot, not a medical device).

## Development workflow

This project is released through versioned full-update ZIP packages, watched by a standalone `solvi-watch.sh` in the cloned Git repository.

1. Run `./solvi-watch.sh` in the repository root.
2. Drop `Solvi_Update_vX.Y.Z.zip` into `updates/` (prefer copying as `.part` and renaming when complete).
3. The watcher validates the manifest/checksums, prepares local Three.js dependencies, runs JavaScript tests and local HTTP smoke checks, stages the app on SSH, backs up the current release, publishes and checks public HTTPS, and then commits locally.
4. Passed archives move to `updates/processed/`; failed archives and detailed error logs move to `updates/failed/`.

By default, deployment overwrites **only the static app paths directly inside** `/var/www/mojoworks/labs/solvi/`, preserving versioned snapshots (`/1/`, `/2/`, etc). Optional `SOLVI_DEPLOY_SUBDIR=2` deploys into snapshot 2 instead.

### Start a local preview

```sh
node download-three.mjs  # initial download only; creates vendor/
node serve.mjs
```

Open `http://localhost:8080/` for the desktop preview. Use trusted HTTPS when opening WebXR from the Quest.

### No front-end framework

The app uses native HTML, CSS, JavaScript modules and Three.js. No React, Vite, webpack, npm install or application backend is required.

### Version history

`releases.json` is generated by the watcher. A small version stamp sits next to the logo. The `[dev]` overlay displays a scrollable changelog, newest release first; hide/show state is remembered in the browser.

The overlay is a desktop/landing-screen element. It is hidden during immersive WebXR sessions, where the 3D panels remain the interaction surface.
